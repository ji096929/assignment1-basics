## 一、Unicode / 编码（unicode1、unicode2）

- `chr(0)` 是 `'\x00'`；它的 repr 和 print 显示不同（一个能看到转义形式，一个看不见）。
- 看不懂 `decode_utf8_bytes_to_str_wrong`：
  - `"".join(列表)` = 把列表里的字符串首尾相接（`join` 前面的 `""` 是分隔符）。
  - 执行顺序：Python 从最内层括号往外算；`for` 决定"哪一段要重复"。
  - 错在哪：UTF-8 是变长编码，一个字符可能占 2~4 字节。把字节拆开逐个解码，要么报
    `UnicodeDecodeError`（Python 3），要么得到乱码 `'Ã©'`（宽容解码器 / Python 2）。
  - 例子：`"é".encode("utf-8")` = `b'\xc3\xa9'`，逐字节解码会炸。
- `b'h'` vs `'h'`：前者是 bytes（元素是 0~255 的整数），后者是 str（元素是字符）。
- `bytes([b])` 为什么必须包一层：迭代 bytes 出来的是 int，而 `.decode()` 是 bytes 对象的方法。
- unicode2(c) 找非法两字节序列：文档没附规范表，要自己查规范或做实验。
  - 合法两字节的规则：首字节 `C2–DF`，第二字节 `80–BF`，缺一非法。
  - 例子：`b'\x80\x80'`（`0x80–0xBF` 是"跟随字节"，永远不能当序列开头）。

## 二、Python 语法（零基础）

- 类型标注（如 `dict[tuple[bytes, ...], int]`）只是**注释**，运行时不检查；读法是"从外往里剥"。
- 元组 = 把几个值捆成一个**不可变**的整体；不可变 → 可哈希 → 能当字典的键。
- `[...]` 用来建列表、**取下标**；`(...)` 用来调用函数、建元组。
- 缩进是语法：**冒号后面，下一行要多缩一级**。
- **定义函数 ≠ 调用函数**：`def` 只是给代码起名字，要另外写 `函数名()` 才会执行。
- `del` 会让后面的元素**整体前移**；边遍历边删时，下标要手动退一步。
- 跨目录 import 不用管目录：`from cs336_basics.tokenizer import ...`（包已经被 uv 装好了）。
- VSCode 解释器要手动指到 `.venv/bin/python`（工作区根目录不是项目根时，自动发现会失败）。

## 三、BPE 概念

- 每轮只挑**一对**合并，但这一对在**所有出现处**都合并。
- 第一轮参与合并的都是单字节；从第二轮起，成员可能是前面合并出来的多字节 token。
- 为什么要先统计词频：把语料压缩成 `{词: 次数}`。
  实测：22MB 文本 → 550 万次出现 → 只有 1.3 万种不同的词（压缩 420 倍）。
  不压缩的话，每轮 merge 都要扫全文，再乘上几千轮，完全不可行。
- 特殊 token：在 `train_bpe` 里只需"进词表、不参与合并"；它的语义（文档边界）是用分词器时才体现。
- `vocab` 只增不减：初始 256 个字节永远在里面，被合并掉的旧 token 也仍然保留。

## 四、环境（WSL / Windows）

- uv 只装在 Windows 侧，WSL 里找不到 → 另装 Linux 版 uv。
- PyPI 下载慢（约 0.6MB/s）→ 配清华镜像后约 7MB/s。（副作用：`uv.lock` 里的 source 被改写）
- 跑 `uv sync` 把 VSCode 卡死：WSL 只有 7.4G 内存，vscode-server 22 个进程占 3G，解压 torch 时打满 swap。
- GPU 不可用：驱动 572 只支持到 CUDA 12.8，而 torch 是 cu130 → 升级驱动到 580.97 后恢复。
- 实测算力（RTX 4050 Laptop 6GB）：bf16 GEMM **24.4 TFLOPS**；CPU 0.25 TFLOPS。差约 100 倍 → 训练一律用 GPU。

## 五、实现 train_bpe 踩的坑（基本都是报错教会的）

- **中文全角逗号 `，`** → SyntaxError，整个文件解析失败，IDE 的补全和自动缩进全部消失。
- `def` 少写冒号 → 同样症状。
- 函数定义完没有调用 → 跑完没有任何输出。
- `Counter(m.group())` 数的是字符串里的**字符**；正确做法：计数器建在循环**外**，循环里 `+= 1`。
- 替换时写 `i += 2`，跳过了本该检查的位置（因为 `del` 让元素前移），应为 `+= 1`。
- `vocab[...] = ...` 写在了"遍历所有词"的循环里 → 每轮其实只该加**一个**新 token。
- 报错读法（`assert` 类型）：`At index 26 diff: A != B` —— A 是我的输出、B 是参考；
  **前面全对说明逻辑是对的**，错误是累积出来的。
